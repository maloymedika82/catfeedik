# 1. Цель проекта

Разработать собственную Telegram Mini App-платформу для организации кормления бездомных кошек и собак.

Пользователь снимает процесс кормления непосредственно в приложении, отправляет видео на AI-модерацию, получает поинты за подтверждённое кормление и участвует в общем рейтинге.

В рамках проекта реализуются:
- Пользовательский Mini App.
- Запись и загрузка видео.
- AI-модерация.
- Антифрод.
- Географическая карта.
- Публичная видеолента.
- Поинты и денежные бонусы.
- Лидерборд.
- Спонсоры и задания.
- Административная панель.
- Ручные криптовалютные выплаты.

Продукт должен иметь собственный исходный код, собственную базу данных и независимую инфраструктуру.

- Мониторинг состояния сервера.

Один VPS сам по себе не обеспечивает восстановление за час: необходим заранее подготовленный сценарий восстановления или резервный экземпляр.

# 4. Авторизация и регистрация

Авторизация осуществляется исключительно через Telegram.

При первом входе:
- Создаётся пользователь.
- Сохраняется Telegram ID.
- Получаются имя и аватар Telegram.
- Определяется язык интерфейса.
- Создаётся профиль.

Регистрация открытая.

Телефонная SMS-регистрация не требуется.

Backend обязательно проверяет подпись Telegram initData. Нельзя доверять Telegram ID, полученному из неподтверждённого клиентского запроса.

Языки приложения:
- Русский.
- Английский.

# 5. Интерфейс Mini App

Главная навигация состоит из трёх кнопок:

1. Главная.
2. Спонсоры.
3. Профиль.

### 5.1. Главная

Содержит:
- Интерактивную карту городов.
- Отметки городов с кормлениями.
- Количество подтверждённых кормлений по городам.
- Лидерборд.
- Кнопку «НАЧАТЬ».

При нажатии на город открывается отдельная вертикальная лента видео этого города.

Публично отображается только город, точные координаты пользователей не раскрываются.

### 5.2. Лидерборд

Отображает:
- Место участника.
- Аватар Telegram.
- Имя.
- Количество поинтов.
- Количество кормлений.
- Призовую сумму, если участник находится на призовом месте.

Все участники отображаются с возможностью прокрутки.

Рейтинг обновляется один раз в час.

### 5.3. Публичная лента

Отдельный экран для каждого города.

Функции:
- Вертикальное воспроизведение видео.
- Имя и аватар автора.
- Дата публикации.
- Лайки.
- Только лайки, без комментариев.

В ленте находятся исключительно одобренные видео.

### 5.4. Спонсоры

Отображаются:
- Логотип.
- Название.
- Описание.
- Активные задания.
- Условия выполнения.
- Награды в поинтах.
- Статус выполнения.

### 5.5. Профиль

Содержит:
- Аватар и имя Telegram.
- Город.
- Количество кормлений.
- Баланс поинтов.
- Позицию в рейтинге.
- Историю видео.
- Историю начислений.
- Прогресс до бонусов.
- Заработанные денежные награды.
- Статусы выплат.
- Криптовалютный кошелёк.
- Настройки языка.

# 6. Запись видео

Запись происходит непосредственно внутри Telegram Mini App.

### Утверждённые параметры

| Параметр | Значение |
|---|---|
| Максимальная длительность | 15 секунд |
| Разрешение | 720p |
| Формат | MP4 / H.264 |
| Частота кадров | Целевая 30 FPS |
| Звук | Включён |
| Тип записи | Непрерывная |
| Дополнительные задания | Нет |

Микрофон и камера запрашиваются отдельными разрешениями.

Скрытая запись после закрытия или сворачивания Mini App запрещена.

### Сценарий записи

1. Пользователь нажимает «НАЧАТЬ».
2. Приложение запрашивает разрешение на камеру.
3. Запрашивается геолокация.
4. Открывается камера.
5. Пользователь записывает кормление.
6. Запись автоматически заканчивается через 15 секунд.
7. Появляется предпросмотр.
8. Пользователь выбирает «Переснять» или «Отправить».
9. Видео загружается на серверное хранилище.

После отправки нельзя изменить содержание видео.

При ошибке загрузки пользователь может повторить загрузку того же файла без создания нового кормления.

# 7. Загрузка и хранение видео

Использовать Cloudflare R2.

Алгоритм:
1. Backend создаёт уникальный ID видео.
2. Выдаёт временную подписанную ссылку.
3. Mini App загружает видео непосредственно в R2.
4. Backend проверяет завершение загрузки.
5. Видео попадает в очередь обработки.
6. Результат проверки сохраняется в PostgreSQL.

Не хранить оригиналы видео на VPS.

Временные файлы автоматически удалять.

После завершения эксперимента и всех апелляций удалить:
- Оригиналы видео.
- Обработанные копии.
- Превью.
- Временные кадры.
- Остаточные файлы обработки.

История кормлений, поинтов и финансовых операций сохраняется в соответствии с установленными сроками хранения.

# 8. AI-модерация

### Основная модель

Предварительный выбор: Google Gemini 3.1 Flash-Lite через сторонний API-провайдер.

Перед production необходимо подтвердить поддержку видеовхода именно у посредника, лимиты файлов, доступность модели и фактическую стоимость.

### Проверяемые условия

AI должен определить:

1. Наличие кошки или собаки.
2. Наличие корма.
3. Реальное поедание корма.
4. Продолжительность кормления.
5. Наличие животного в кадре большую часть видео.
6. Последовательность событий.
7. Признаки повторного использования видео.

### Алгоритм

Первичная проверка:
- Извлечение кадров через FFmpeg.
- Начальная частота анализа 2–3 кадра в секунду.
- Передача кадров или видеоматериала в Gemini.
- Получение структурированного результата.

Дополнительно необходимо сравнить прямую передачу видео в Gemini с выборочным анализом кадров и выбрать лучший вариант по цене и качеству.

### Результаты

Три возможных решения:

- APPROVE — одобрить.
- REJECT — отклонить при очевидном нарушении.
- REVIEW — передать администратору.

Сомнительные видео всегда передаются Admin.

AI не имеет права самостоятельно начислять поинты.

Начисление происходит только после успешной проверки Backend.

### Защита от повторной проверки

Результат каждой проверки сохраняется.

Повторная AI-проверка уже обработанного видео не запускается без специального основания.

При технической ошибке запрос может быть повторён. Техническая ошибка не считается основанием для отказа.

# 9. Начисление поинтов

### Основное правило

За каждое одобренное кормление:

**+10 поинтов.**

Одно видео — один зачёт.

### Бонус за пять кормлений

При достижении пяти подтверждённых кормлений:

**+5 поинтов единоразово.**

### Бонус за десять кормлений

При достижении десяти подтверждённых кормлений:

**$5 единоразово.**

Бонус выдаётся при наличии свободного бюджета.

После исчерпания бюджета новые денежные бонусы не выдаются.

Уже зарезервированные награды сохраняются.

### Семидневное ограничение

- Действует отдельно для каждого пользователя.
- Ограничение привязано к локации, а не к животному.
- Одно и то же животное может кормиться разными участниками.
- Один пользователь может снова получить зачёт в той же локации после семи дней.
- Кормление в другой локации может засчитываться независимо от предыдущей.

Радиус определения одной локации и точность GPS необходимо настроить отдельно.

Идентификация конкретных животных не требуется.

### История поинтов

Все начисления и списания хранятся в Points Ledger.

Нельзя просто изменять баланс без отдельной транзакции.

# 10. Геолокация

При записи видео пользователь предоставляет разрешение на геолокацию.

Система:
- Получает координаты.
- Определяет город.
- Сохраняет координаты в закрытой части базы.
- Использует локацию для проверки семидневного ограничения.
- После одобрения учитывает кормление в статистике города.

Публично показывается только город.

Геолокация не является самостоятельным доказательством подлинности кормления.

# 11. Антифрод

### Собираемые технические данные

При наличии законного основания и с информированием пользователя:
- IP-адреса обращений.
- Telegram ID.
- Тип устройства.
- Операционная система.
- Версия Telegram и браузера.
- Время авторизаций.
- История действий.
- Разрешённая геолокация.
- История видео.

Не пытаться получать недоступные браузеру идентификаторы устройств, IMEI или серийные номера.

### Уровни риска

| Уровень | Действие |
|---|---|
| Низкий | Наблюдение |
| Средний | Автоматическая заморозка |
| Высокий | Автоматическая заморозка |

Один IP-адрес или общая сеть не являются достаточным доказательством нарушения.

### При заморозке

- Новые видео отправлять нельзя.
- Задания недоступны.
- Начисления приостанавливаются.
- Выплаты приостанавливаются.
- Ожидающие видео автоматически отклоняются по причине заморозки.
- История проверок сохраняется.
- Пользователь может обратиться в поддержку.

### Проверка личности

При подозрительной активности может потребоваться дополнительная идентификация.

Способ проверки и внешний KYC-сервис выбираются отдельно.

Не хранить документы и селфи без необходимости и соответствующих мер защиты.

### Разморозка

Администратор может разморозить пользователя после проверки.

Все действия фиксируются.

# 12. Лидерборд

Сортировка:

1. Больше поинтов.
2. При равенстве — больше подтверждённых кормлений.
3. При равенстве — кто раньше достиг итогового результата.

Количество призовых мест зависит от бюджета и определяется Owner.

### Завершение эксперимента

- Приём новых кормлений прекращается по дедлайну.
- Видео, записанные до дедлайна, могут быть обработаны позже.
- Завершаются проверки и апелляции.
- Формируется финальный рейтинг.
- Owner утверждает победителей и призовые суммы.
- Рейтинг окончательно фиксируется.
- Начинаются выплаты.

# 13. Финансовая система

### Бонусный фонд

Пример бюджета: $100.

- Один бонус — $5.
- Максимум 20 бонусов.
- Бюджет фиксируется при запуске.
- Пополнение после запуска запрещено.
- При исчерпании бюджета новые бонусы не выдаются.

Бонус резервируется за участником при достижении условий.

Порядок распределения — по времени достижения десяти подтверждённых кормлений.

### Призы лидерборда

Отдельный бюджет, не связанный с бонусами за десять кормлений.

Размеры призов и количество мест определяет Owner.

### Криптовалютные выплаты

- Выплаты выполняются вручную.
- Валюта учёта — USD.
- Конкретная криптовалюта пока не выбрана.
- Сеть пока не выбрана.
- Кошелёк пользователь указывает в профиле.
- Приватные ключи и seed-фразы не запрашиваются.

Owner самостоятельно отправляет перевод и записывает TXID.

Система хранит:
- Получателя.
- Сумму.
- Валюту.
- Сеть.
- Адрес.
- TXID.
- Дату.
- Статус.

Необходимо исключить двойную выплату одной награды.

- Видео одобрено.

# 19. Оптимизация расходов

Обязательные решения:

1. Видео хранить в Cloudflare R2.
2. Не оплачивать собственный GPU.
3. Использовать внешний AI API.
4. Сначала анализировать ограниченную выборку кадров.
5. Полный анализ использовать при необходимости.
6. Не запускать повторную AI-проверку без причины.
7. Автоматически удалять временные файлы.
8. Не создавать отдельный сервер для каждой функции.
9. Использовать один основной VPS.
10. Хранить резервные копии отдельно.
