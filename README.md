# Catfeedik

Telegram Mini App для помощи бездомным животным. React 19 + TypeScript + Vite + Tailwind 4; FastAPI + SQLAlchemy; PostgreSQL 17/PostGIS и Redis в Docker.

## Локальный запуск

```sh
cd /workspace/catfeedik
npm ci
uv venv .venv
uv pip install --python .venv/bin/python -r backend/requirements.lock
python3 scripts/init-local.py
docker compose --env-file .local/services.env up -d --wait
.venv/bin/python scripts/dev-api.py
# В другом терминале:
npm run dev -- --port 5174
```

`init-local.py` создаёт случайный пароль только локальной БД, не заменяет существующие файлы. API читает настройки в порядке: внедрённое окружение, `.env`, `.local/services.env`. Последний файл включает тестовый вход; он действует только при `APP_ENV=development` и `ALLOW_DEV_LOGIN=1`. Тестовый пользователь имеет отрицательный Telegram ID и не смешивается с настоящими пользователями. В production установите `APP_ENV=production`, `ALLOW_DEV_LOGIN=0`, используйте HTTPS и отдельную БД. Docker-порты привязаны к loopback. Redis запущен, но Celery ещё не подключён.

При восстановлении облачной среды процессы API/Vite и контейнеры необходимо запускать снова. Используйте существующий checkout; отдельный worktree не нужен.

## Telegram и хранилище

Скопируйте `.env.example` в `.env` и внесите реальные значения только в защищённой среде. Никогда не коммитьте `.env`. Для полноценной авторизации нужен `TELEGRAM_BOT_TOKEN`, для Owner — `OWNER_TELEGRAM_IDS` (список числовых ID). Bot token используется локально для HMAC и должен быть настоящим runtime-секретом, а не подстановкой сетевого прокси. В BotFather позже укажите публичный HTTPS URL приложения; домен и развёртывание пока не настроены. Проверка серверной подписи initData тестируется локально, реальный бот ещё не подключён.

Для R2 нужны `R2_ENDPOINT_URL`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`. Подпись S3 создаётся локально, нужны настоящие runtime-секреты. Bucket должен быть приватным. CORS: разрешён только домен Mini App; PUT; заголовки Content-Type и If-None-Match. Загрузка использует условный PUT, не допускающий перезапись объекта. После успешной загрузки API проверяет размер и тип через HEAD и отправляет видео в ручную очередь. Повтор использует тот же request_key и ID; оригинал не хранится постоянно на VPS. Реальная R2-загрузка пока не проверялась.

Без утверждённого `MAX_VIDEO_BYTES` загрузка запрещена. Без `LOCATION_RADIUS_METERS` и `MAX_GPS_ACCURACY_METERS` одобрение запрещено. Эти параметры открыты в ТЗ: не подставляйте произвольные production-значения. Значения в тестах относятся только к тестовым схемам.

## Реализовано

- Адаптивные Главная / Спонсоры / Профиль; настоящие серверные данные и пустые состояния вместо фиктивных метрик.
- Telegram SDK, проверка HMAC initData, срока действия, повторяющихся полей; серверные сессии с хешем токена, выход.
- Профиль и история начислений/видео в БД; роли USER / ADMIN / OWNER, Owner задаётся серверной конфигурацией.
- Камера и микрофон отдельными разрешениями; геолокация; непрерывная запись до 15 секунд; предпросмотр, пересъёмка, освобождение камеры при закрытии/сворачивании.
- Приватные R2 presigned upload/read URLs; повторяемая загрузка без создания нового кормления; проверка принадлежности видео.
- Общая очередь, эксклюзивное закрепление, просмотр по временной ссылке, решение с причиной, журнал. Owner может вернуть видео в очередь через API.
- Транзакционное +10; однократное +5 за 5 кормлений; уникальные события ledger и блокировки PostgreSQL. Проверена конкурентная повторная обработка одного видео.
- Ограничение повторного зачёта по расстоянию и интервалу 7 дней отдельно для участника; точные координаты не возвращаются публичными endpoints.
- Почасовые снимки рейтинга с сортировкой по поинтам, количеству и времени достижения; пагинация. Снимок создаётся при первом запросе в час, не фоновым планировщиком.
- Заморозка через API: запрет отправки/изменения профиля/одобрения, ожидающие видео отклоняются, история сохраняется.

## Проверки

```sh
npm run build
.venv/bin/python -m pytest backend/tests -q
.venv/bin/python scripts/test-postgres.py
# Если Python Playwright + Chromium доступны, API и Vite запущены:
python3 scripts/check-browser.py
python3 scripts/check-camera.py
```

PostgreSQL-тесты создают отдельные случайные схемы и удаляют только их. Тесты SQLite — вспомогательные; row locks требуют PostgreSQL. Короткая диагностика API — `/api/health`, документация — `/docs`. Не публикуйте dev API без отдельной настройки безопасности.

SL UI `matte-dock-navigation` / `dock-navigation`: сохранён полный исходный пакет, исходные SVG, контроллер и cleanup. React Dock монтирует оригинальный vanilla-контроллер через effect с cleanup, адаптирует только подписи/раскладку. SHA-256: `docs/source-receipts.json`; аудит сериализованного DOM: `docs/source-audit.json`. Аналитика и автообновления не включены.

## Ещё не готово к запуску эксперимента

Нет Celery/FFmpeg pipeline, проверки фактического медиаформата/длительности на сервере, AI Gemini, проверки дубликатов видео, публичного видеоплеера/лайков, апелляций, финансового ledger и резерва бонуса $5, денежных выплат, спонсорских интеграций, английского UI, полной админ-панели и бот-уведомлений. Значения бюджета/сроков эксперимента не выдуманы. Призы и денежные бонусы не начисляются. Формат записи зависит от браузера; MP4/H.264/720p надо обеспечивать серверной обработкой.

До production нужны versioned migrations (сейчас create_all для первого запуска), ограничения запросов и аудит безопасности, секреты, выбранные параметры ТЗ, резервирование/WAL/проверка восстановления, мониторинг, хранение и очистка видео, HTTPS/деплой и реальные проверки Telegram iOS/Android. Камера проверяется виртуальными устройствами Chromium, не реальными телефонами. Docker volumes — локальное хранилище, не резервная копия.
