# Catfeedik

Telegram Mini App для помощи бездомным животным. React 19 + TypeScript + Vite + Tailwind 4; FastAPI + SQLAlchemy; PostgreSQL 17/PostGIS и Redis в Docker.

## Локальный запуск

```sh
cd /workspace/catfeedik
npm ci
uv venv .venv
uv pip install --python .venv/bin/python -r backend/requirements.lock
python3 scripts/init-local.py
docker compose --env-file .local/services.env up -d --wait
.venv/bin/python scripts/dev-api.py
# В другом терминале:
npm run dev -- --port 5174
# В третьем терминале (установите FFmpeg/FFprobe):
.venv/bin/python scripts/dev-worker.py
```

`init-local.py` создаёт случайный пароль только локальной БД, не заменяет существующие файлы. API читает настройки в порядке: внедрённое окружение, `.env`, `.local/services.env`. Последний файл включает тестовый вход; он действует только при `APP_ENV=development` и `ALLOW_DEV_LOGIN=1`. Тестовый пользователь имеет отрицательный Telegram ID и не смешивается с настоящими пользователями. В production установите `APP_ENV=production`, `ALLOW_DEV_LOGIN=0`, используйте HTTPS и отдельную БД. Docker-порты привязаны к loopback. Celery использует Redis для очереди и каждые 15 секунд подбирает сохранённые задания, переживая недоступность брокера при отправке видео.

При восстановлении облачной среды процессы API/Vite и контейнеры необходимо запускать снова. Используйте существующий checkout; отдельный worktree не нужен.

## Telegram и хранилище

Скопируйте `.env.example` в `.env` и внесите реальные значения только в защищённой среде. Никогда не коммитьте `.env`. Для полноценной авторизации нужен `TELEGRAM_BOT_TOKEN`, для Owner — `OWNER_TELEGRAM_IDS` (список числовых ID). Bot token используется локально для HMAC и должен быть настоящим runtime-секретом, а не подстановкой сетевого прокси. В BotFather позже укажите публичный HTTPS URL приложения; домен и развёртывание пока не настроены. Проверка серверной подписи initData тестируется локально, реальный бот ещё не подключён.

Видео теперь хранятся на том же сервере, что и приложение. R2/Cloudflare не нужны; старые `R2_*` строки в вашем локальном `.env` игнорируются и могут быть удалены. В `.env` доступны:

```dotenv
VIDEO_STORAGE_DIR=.local/videos
VIDEO_MIN_FREE_BYTES=536870912
```

Первое поле — приватный каталог видео (по умолчанию `.local/videos` внутри проекта). Для VPS можно указать абсолютный путь вне публичных каталогов, например `/srv/catfeedik-videos`, и выдать пользователю backend права записи. Внутри checkout разрешено хранение только под `.local`; под `public`, `src`, `dist` сохранять нельзя. Каталог не публикуется как статика, Vite также запрещает чтение `.local`. `VIDEO_MIN_FREE_BYTES` — технический резерв свободного места (512 MiB), а не бюджет эксперимента: при нехватке места загрузки прекращаются. Файловая система должна поддерживать hard links; на Windows используйте NTFS.

Схема: API создаёт ID → приложение отправляет двоичный файл авторизованным PUT → API пишет ограниченный поток во временный файл → оригинал публикуется атомарно без перезаписи → отдельный запрос complete переводит кормление в PROCESSING и сохраняет задание обработки в БД. Сессия повторяется с тем же ID; содержимое уже сохранённого файла нельзя заменить, даже если размер совпадает. Размер проверяется по фактически принятым байтам, а не только Content-Length. Неуспешные запросы удаляют свои временные файлы, после перезапуска удаляются незавершённые `.part` старше суток. Завершённые оригиналы автоматически не удаляются: сроки хранения и апелляций ещё не утверждены.

Просмотр `/api/media/{id}` разрешён только автору или ADMIN/OWNER. Браузерный видеоплеер использует HttpOnly cookie сессии, ограниченную read-only путём `/api/media`; остальные API требуют Bearer. Cookie защищена Secure в production. Поддерживаются Range-запросы для перемотки; ответы private/no-store. После обновления войдите заново, чтобы браузер получил cookie. Существующие объекты R2 не переносятся автоматически; их ключи в старых записях останутся без локальных файлов, пока отдельная миграция не перенесёт оригиналы.

Это изменение пользовательского решения заменяет требование R2 в разделах 7 и 19 исходного ТЗ; оригинальный документ сохранён без исправлений. Место на диске и канал VPS теперь расходуются на видео. Резервную копию БД и необходимых видео храните отдельно от VPS; локальный диск не является резервной копией.

Пользователь поручил выбрать тестовые параметры: в APP_ENV=development пустые значения означают MAX_VIDEO_BYTES=20971520 (20 МиБ), LOCATION_RADIUS_METERS=100, MAX_GPS_ACCURACY_METERS=50. Явные значения .env имеют приоритет. В APP_ENV=production значения по умолчанию не используются: лимиты должны быть явно утверждены и заполнены. Денежные бонусы и выплаты выключены по указанию владельца; API сообщает money_enabled=false, финансовые операции не выполняются.

## Реализовано

- Адаптивные Главная / Спонсоры / Профиль; настоящие серверные данные и пустые состояния вместо фиктивных метрик.
- Telegram SDK, проверка HMAC initData, срока действия, повторяющихся полей; серверные сессии с хешем токена, выход.
- Профиль и история начислений/видео в БД; роли USER / ADMIN / OWNER, Owner задаётся серверной конфигурацией.
- Камера и микрофон отдельными разрешениями; геолокация; непрерывная запись до 15 секунд; предпросмотр, пересъёмка, освобождение камеры при закрытии/сворачивании.
- Приватное локальное хранилище, потоковая загрузка с ограничением размера/места, неизменяемые оригиналы и повторная отправка в одну сессию; проверка принадлежности видео.
- Celery + Redis + FFmpeg: проверка MP4/WebM, звука и длительности (15 секунд + 0,5 с допуск входа), обрезка выхода до 15 с, H.264/AAC/30 FPS, до 720p, удаление метаданных, JPEG-превью. WebM без Duration проверяется по ограниченной выборке пакетов. Технические ошибки повторяются до трёх раз и не считаются нарушением.
- Мировая карта Leaflet + OpenStreetMap, центрирование/масштабирование, отметки подтверждённых городов. Ближайший город определяется локальным GeoNames (каталог городов от 15 тыс. жителей); это не геокодирование административных границ. Публичные координаты — только центры из каталога, никогда среднее/округление реальных GPS. Атрибуция OSM и GeoNames показана в интерфейсе. Карта обновляет счётчики раз в 30 секунд.
- Вертикальная городская лента только одобренных и обработанных видео, превью, Range, пагинация, лайки после входа без комментариев. Оригиналы остаются приватными.
- AnyModel vision adapter по OpenAI-compatible контракту: ограниченные JPEG-кадры, структурированный ответ, пороги уверенности, технические ошибки и неопределённость -> REVIEW. SHA-256 повторы файлов -> ручная проверка, без автоматического наказания аккаунта. AI не пишет поинты: отдельная серверная проверка блокировок/GPS/7 дней и транзакционный ledger. Повтор неуспешного AI использует существующий MP4 и не запускает FFmpeg заново.
- Общая очередь, эксклюзивное закрепление, просмотр по авторизованному API, решение с причиной, журнал. Owner может вернуть видео в очередь через API.
- Транзакционное +10; однократное +5 за 5 кормлений; уникальные события ledger и блокировки PostgreSQL. Проверена конкурентная повторная обработка одного видео.
- Ограничение повторного зачёта по расстоянию и интервалу 7 дней отдельно для участника; точные координаты не возвращаются публичными endpoints.
- Почасовые снимки рейтинга с сортировкой по поинтам, количеству и времени достижения; пагинация. Снимок создаётся при первом запросе в час, не фоновым планировщиком.
- Заморозка через API: запрет отправки/изменения профиля/одобрения, ожидающие видео отклоняются, история сохраняется.

```sh
npm run build

.venv/bin/python scripts/test-postgres.py
# Если Python Playwright + Chromium доступны, API и Vite запущены:
```

PostgreSQL-тесты создают отдельные случайные схемы и удаляют только их. Тесты SQLite — вспомогательные; row locks требуют PostgreSQL. Короткая диагностика API — `/api/health`, документация — `/docs`. Не публикуйте dev API без отдельной настройки безопасности.

SL UI `matte-dock-navigation` / `dock-navigation`: сохранён полный исходный пакет, исходные SVG, контроллер и cleanup. SHA-256: `docs/source-receipts.json`; аудит сериализованного DOM: `docs/source-audit.json`. Аналитика и автообновления не включены.

Антифрод сейчас проверяет точное совпадение файла; устойчивое распознавание обрезанных/перекодированных дубликатов ещё не реализовано. Значения бюджета/сроков эксперимента не выдуманы. Призы и денежные бонусы не начисляются. Исходный формат зависит от браузера; публичные копии нормализуются FFmpeg. Валидация видео и Like не доказывает достоверность его содержимого: остаются AI/ручная проверка и антифрод.

Камера проверяется виртуальными устройствами Chromium, не реальными телефонами. Docker volumes — локальное хранилище, не резервная копия.

## AnyModel и ключ

Бот владельца: @animalfeedikbot, Owner Telegram ID 2022054034. Роль назначается только после проверки подписи Telegram, а не по ID от клиента. OWNER_TELEGRAM_IDS можно переопределить серверной конфигурацией.

Ключ, присланный в чат, не сохранён и не использовался. Его нужно отозвать в AnyModel. Новый ключ храните только в приватном .env:

```dotenv
AI_BASE_URL=https://anymodel.org/v1
AI_API_KEY=
AI_MODEL=auto
```

`auto` запрашивает /models и выбирает реальный возвращённый ID Gemini Flash (предпочитает lite, затем стабильную версию). API-посредник должен поддерживать image_url и JSON-ответ в /chat/completions; это пока проверено только HTTP-моками, не настоящим провайдером. Если список моделей или vision недоступны, используется ручная проверка. Точный поддерживаемый ID можно указать в AI_MODEL. Команда `.venv/bin/python scripts/ai-models.py` выводит только Gemini ID, без ключей/ответов ошибок. В Windows используйте `.venv\Scripts\python.exe`.

Перед отправкой пользователь видит уведомление о возможной передаче кадров AI-провайдеру. API получает JPEG без координат и метаданных, но видимые детали сцены остаются на изображениях. Не загружайте лишние персональные данные. Ошибки AI не отклоняют кормление автоматически. AI ERROR/NOT_CONFIGURED можно повторить после настройки; DONE никогда не повторяется автоматически. Подтверждённый человеком результат не переписывается.

## Обновление и запуск на Windows

Закройте старые окна API/Vite перед запуском новых. В CMD из папки проекта:

```cmd
git pull origin main
winget install -e --id Gyan.FFmpeg
```

После установки FFmpeg откройте новую CMD. В проекте выполните `scripts\setup-local.cmd`, затем `scripts\start-dev.cmd`. Существующий `.env` не перезаписывается. Откроются три окна: API, Celery+beat, Vite. Docker Desktop должен работать. Windows-скрипты подготовлены и проверены по содержимому; выполнение проверялось на Linux, не на реальном Windows-хосте. Celery на Windows используется с solo pool для разработки; production планируется на Linux.

Состояние PROCESSING означает ожидание/выполнение фонового задания. Если worker не запущен, видео не потеряется и останется в очереди БД. Уже существующие старые REVIEW/APPROVED записи без video_assets нужно поставить на техническую обработку скриптом scripts/backfill-media.py; старые начисления не повторяются.

## Карта и внешняя сеть

Видеофайлы, БД и очередь находятся на вашем сервере. Подложка карты загружается из https://tile.openstreetmap.org; публичные тайлы без ключа подходят для разработки и небольшого использования в рамках https://operations.osmfoundation.org/policies/tiles/. Для нагрузки выберите подходящий тайл-сервис и задайте VITE_MAP_TILE_URL при сборке. Сохраняйте требуемую атрибуцию. Офлайн-загрузка/массовое скачивание тайлов не используются.

В текущей облачной среде исходящие запросы к AnyModel и OSM были запрещены политикой. Домены добавлены в черновик сетевых настроек для review/publish; это не доказывает применение правил. Браузерный тест использует явно тестовые тайлы и проверяет Leaflet/маркеры/переходы; реальная доставка тайлов здесь не подтверждена. На локальном Windows доступ зависит от вашей сети.

## Проверка реальной vision-модели на вашем компьютере

После настройки AI_API_KEY и AI_MODEL в приватном .env выполните:

```cmd
git pull origin main
.venv\Scripts\python.exe scripts\check-ai.py
```

Проверка делает два небольших запроса с синтетической картинкой: модель должна прочитать девять случайных цветов из изображения, затем не принять цветную сетку за кормление. Названия моделей, PASS/FAIL и безопасные поля результата можно прислать для диагностики; ключи и сырые ответы ошибок не выводятся. Видео, публикации, аккаунты и начисления не создаются. Успешная проверка показывает работоспособность vision и JSON-контракта, а не качество модерации настоящих кормлений или работу камеры/очереди на вашем Windows-компьютере.

Если check-ai.py получает HTTP 429, это ответ провайдера, а не подтверждение поддержки изображений. Самопроверка выводит только безопасную категорию ограничения (квота/баланс, частота запросов, мощность модели либо неизвестно) и Retry-After в секундах, когда провайдер его сообщил. Сырые тела ошибок и ключи не печатаются. Автоматических повторов в самопроверке нет: сначала проверьте баланс/квоту и доступность выбранной модели в кабинете AnyModel.

## Администрирование и апелляции

Отдельная страница `/admin.html`: обзор, модерация, поиск по имени/городу/Telegram ID, профиль и история участника, корректировка поинтов с причиной, заморозка/разморозка, апелляции, журнал. В production войдите через Telegram Mini App и перейдите в админку из профиля под ролью Admin/Owner. Обычный пользователь получает отказ от сервера на административные endpoints.

В development при ALLOW_DEV_LOGIN=1 доступен отдельный вход «Тестовый администратор» (ID -2, роль ADMIN, не OWNER). ALLOW_DEV_ADMIN=0 запрещает вход и существующие тестовые Admin-сессии; APP_ENV=production запрещает все отрицательные тестовые ID, включая просмотр медиа. Не размещайте development-режим публично. Назначить/снять роль ADMIN может только настоящий Owner; роль OWNER определяется серверной конфигурацией.

Корректировки поинтов содержат старый/новый баланс, размер, причину, администратора и время. Повтор одного request_key возвращает сохранённую квитанцию и не меняет баланс второй раз, включая конкурентные POST. Другие данные с тем же ключом отклоняются. Нулевые операции, пустые причины, отрицательный итоговый баланс и изменения замороженному участнику не допускаются. Это операции поинтов, не выплаты денег; money_enabled остаётся false.

Участник подаёт одну апелляцию на отклонённое видео из «Профиль → Мои видео», минимум 10 символов причины. Уже отправленная апелляция не редактируется. Первоначально отказавший модератор не может её закрепить или решить, даже если он Owner. Другой Admin берёт её в работу; принятие вновь проверяет техническую готовность, GPS, 7 дней и заморозку и начисляет поинты транзакционно один раз. Если нужна повторная техническая обработка, отклонённый статус и баланс сохраняются до отдельного решения по апелляции. Срок подачи пока не ограничен, поскольку дедлайн эксперимента ещё не настроен; перед production нужно утвердить срок.

## Ограничения AI и ручной режим

Реальный провайдер AnyModel возвращал пользователю 429 на обе модели gc; страница состояния показывала сбои Gemini. Восстановление провайдера не подтверждено. Ни заголовок Retry-After:60, ни наличие модели в /models не доказывают производительность «одно видео в минуту».

Worker сохраняет Retry-After в БД: до этого времени повтор не выполняется. Пауза общая для всех видео и моделей на том же ключе/адресе провайдера; хранится только необратимый отпечаток ключа, не сам ключ. Техническая обработка и ручная очередь продолжаются. Ожидание не расходует попытки; фактические неудачные запросы ограничены тремя, успешные AI-проверки не повторяются автоматически. Перезапуск Worker или кнопка ручного повтора не обнуляют общую паузу. AI_REQUEST_INTERVAL_SECONDS (по умолчанию1) задаёт минимальный интервал до возникновения ограничения, а не обещанную квоту провайдера.

Owner может остановить/включить автоматическую AI-проверку в «Админка → Обзор», указав причину; действие сохраняется в БД и журнале. AI_MODERATION_ENABLED=0 задаёт начальный ручной режим, если Owner ещё не сохранял выбор. Приостановка автоматики до завершения уже начатого запроса предотвращает автоматическое решение/начисление по его результату. Отдельная CLI-проверка check-ai.py не создаёт видео и не использует очередь или её паузу — запускайте её отдельно, не многократно подряд.

Обновление этих функций добавляет только новые таблицы через текущий development create_all; существующие видео, поинты и приватный .env сохраняются. Для production по-прежнему нужны версионируемые миграции, отдельная БД/конфигурация и проверка развёртывания.

## Спонсоры и задания

В admin.html Owner доступны «Спонсоры» и «Заявки на задания». Создание партнёра и задания требует причины; публикация включается отдельно. Укажите название, условия, целую награду в поинтах и срок в местном времени. Без опубликованных партнёров пользователь видит честное пустое состояние.

Участник отправляет текстовое подтверждение и необязательную HTTPS-ссылку. Проверка ручная, только Owner: внешние сервисы не подтверждают выполнение автоматически. Заявки и доказательства доступны самому участнику и Owner. Отклонённую заявку можно подать заново до срока. После первой заявки условия, награда и срок фиксируются; выключение задания останавливает новые заявки, сохраняя своевременно отправленные. Одобрение начисляет награду один раз за пару участник/задание и не увеличивает число кормлений. История и аудит сохраняются. Эти функции не включают деньги или расчёты со спонсорами.

В development новые таблицы создаются при старте API. В production схема управляется миграциями Alembic; порядок обновления описан в [docs/deployment.md](docs/deployment.md). Дополнительных переменных .env для этого раздела нет. Тестовый Admin не является Owner: управление партнёрами требует настоящей проверенной сессии владельца Telegram.

## Сервер и Telegram

Подготовлен отдельный серверный Compose с Caddy/HTTPS, React-сборкой, API/FFmpeg, Worker, Beat, PostgreSQL и Redis. Инструкция: [docs/deployment.md](docs/deployment.md). Для создания приватного шаблона используйте `python3 scripts/init-production.py`. Тестовый сервер уже работает через Tailscale Funnel по адресу `https://catfeedik-test.tail16d0b1.ts.net/`; собственный домен для этого варианта не требуется.

Для открытия Telegram Mini App с домашнего Windows-компьютера без VPS: [локальный запуск через HTTPS-туннель](docs/telegram-local.md), скрипт `scripts\start-telegram-local.cmd`. Тестовые входы отключаются; ngrok подключается отдельно на самом компьютере.

Перед первым кормлением сохраняется явное согласие с версией условий и описанным использованием данных. Повторная форма не нужна до изменения документа. Условия доступны внизу страницы; системные разрешения Telegram/iOS остаются отдельными. Подробности: [docs/participation-consent.md](docs/participation-consent.md).
